# 云岭青心 · 前后端对齐契约

> 前端和后端在两台电脑上分别开发，靠这份文档和 `contracts/` 目录对齐。
> 冲突时的优先级：`contracts/src/*.ts`（代码）＞ 本文 ＞《技术路径》＞《产品说明》。
> 后端开发者请直接读 `docs/后端交接说明.md`，本文是两边共用的约定。

## 3. 两端怎么对接

前端的数据来源有三种模式，由环境变量决定（Web 用 `VITE_API_MODE`，小程序用 `TARO_APP_API_MODE`）：

| 模式 | 行为 |
|---|---|
| `auto`（默认） | 启动时探测 3000 端口的 `/health`：通了就连后端，不通就用内置的模拟后端 |
| `http` | 只连后端 |
| `mock` | 只用内置模拟后端（每个端各自一份内存数据，互不相通） |

所以：

- **前端单独开发**：什么都不用起，直接 `npm run dev:web`，页面右下角显示“内置演示数据”。
- **三端联动演示**（学生求助 → 班主任立刻看到）：先 `npm run mock` 或启动真实后端，再启动前端，右下角显示“已连接后端”。
- **后端做好之后**：前端不用改任何代码。

小程序在微信开发者工具或真机上运行时，把 `TARO_APP_API_ORIGIN` 设成电脑的局域网地址。

## 4. 接口约定

| 项 | 约定 |
|---|---|
| 前缀 | `/api/v1` |
| 数据格式 | JSON，字段 `snake_case`；时间 ISO 8601 UTC；id 是不透明字符串 |
| 成功响应 | 直接返回资源对象，不包外壳；分页列表返回 `{ items, next_cursor }` |
| 错误响应 | RFC 9457，`Content-Type: application/problem+json`，前端按 `code` 分支 |
| 鉴权 | `Authorization: Bearer <access_token>` |
| 目的码 | `X-Purpose-Code: PUR-0x`，哪个接口要哪个码写在路由表里，前端的 `api()` 自动带 |
| 幂等 | 非 GET 请求带 `Idempotency-Key`，前端的 `api()` 自动带 |
| 分页 | `?cursor=&limit=`，limit 默认 20、上限 100 |

错误码：`UNAUTHENTICATED`(401) `FORBIDDEN`(403) `PURPOSE_DENIED`(403) `CONSENT_REQUIRED`(403) `NOT_FOUND`(404) `CONFLICT`(409) `ILLEGAL_TRANSITION`(409) `VALIDATION_FAILED`(422) `RATE_LIMITED`(429) `INTERNAL`(500)。

前端调用的写法（Web 与小程序相同）：

```ts
const page = await api<Page<AlertItem>>(Routes.alertList);
await api<AlertItem>(Routes.alertAck, { params: { id } });
```

## 7. 两端都必须守住的产品红线

1. 学生和家长能看到的任何页面、任何响应里，不出现 `L1/L2/L3`、“风险”“高危”“抑郁”等字样。
2. 所有采集都能跳过；不显示倒计时、排名、连续打卡天数。
3. 家长只看到摘要，没有分数、逐题作答、逐日记录、咨询内容。
4. 聚合数据样本数小于 10 时返回 null，页面显示“样本不足 10 人，暂不展示”；不做学校排名。
5. AI 回复带标识和来源；出现危机表达时停止对话并展示求助入口；AI 不查询任何个案数据。
6. 成长圈里学生只显示昵称，没有私信，新用户发言先审后发。
7. 娱乐量表不保存、不触发提醒、不给老师和家长看。
8. 支持等级在教师端用“文字 + 形状”展示，不只靠颜色。
9. 系统只提示，等级由人确认；误报不追责。
10. 对外文案不出现“学习强国”；产品名用“云岭青心 · 青少年成长学习与资源协同平台”。

## 8. 改契约的规则

- 可以直接做：新增接口、给响应加可选字段、给请求加可选参数。改完同步更新 `contracts/src/mock/`，保证 `npm run mock` + `npm run accept` 全部通过。
- 需要两边先商量：改名、删字段、可选改必填、改变含义、改状态码或错误码。
- 改完执行 `npm run build:contracts`（小程序和后端读的是构建产物）。
