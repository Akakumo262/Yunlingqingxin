# 云岭青心 · 成员上手指南

> 拿到这个仓库或代码包的每一个人，从这里开始。先做第 1 节，再按自己的分工跳到对应的小节。
> 你不需要读完所有文档：每个分工只列了必须知道的事和要读的那一份。

## 1. 所有人：三条命令

需要 Node.js 22 或更高（<https://nodejs.org> 装长期支持版）。不需要数据库，不需要 Docker，不需要任何账号和密钥。

```bash
npm run setup     # 第一次：装依赖、构建契约包。官方源装不上会自动换国内镜像
```

```bash
npm run demo      # 同时启动 模拟后端 + 教师端 + 学生端预览，按 Ctrl+C 一起停
```

```bash
npm run check     # 全量自检：类型检查 + 68 项验收。提交之前跑一次
```

Windows 上不想开命令行的，直接双击根目录的 `启动演示.bat`，它会自己安装、启动并打开浏览器。

启动后：

| 地址 | 是什么 | 怎么进 |
|---|---|---|
| <http://localhost:5173> | 教师端 / 管理端 | 登录页下方直接点一个身份 |
| <http://localhost:10086> | 学生端 / 家长端（小程序的浏览器预览） | 首页直接点“我是学生”或“我是家长” |
| <http://localhost:3000/api/v1> | 后端接口（默认是模拟后端） | — |

所有数据都是合成的；模拟后端的数据在内存里，重启就还原。

## 2. 仓库里有什么

```
contracts/          两端共用的契约：118 个接口、类型、内容库、模拟后端、68 项验收
frontend/web/       教师端 + 管理端（React + Ant Design），26 个页面
frontend/miniapp/   学生端 + 家长端（Taro：微信小程序 + 浏览器预览），18 个页面
frontend/design/    设计令牌（颜色、圆角、字体）
backend/            后端起步骨架（NestJS + PostgreSQL），待开发
docs/               本文、前后端对齐契约、后端交接说明
tools/              setup / demo / check / pack 四个脚本
```

一句话理解分工：**`contracts/` 是所有人的共同语言**。接口长什么样、数据长什么样、行为应该是什么，都只在那里定义一份；前端照着它画页面，后端照着它实现，测试照着它验收。

## 3. 按分工看

### 3.1 我要演示、讲解、截图（不写代码）

1. `npm run demo`（或双击 `启动演示.bat`），把两个地址各开一个浏览器窗口，并排放。学生端的窗口拉窄一点，像手机。
2. 照 `README.md` 里“演示时可以这样走一遍”的六步走。每一步都是“一边做了什么，另一边立刻变了什么”。
3. 想恢复到初始数据：Ctrl+C 停掉，重新 `npm run demo`。
4. 讲解时守住的口径在 `docs/前后端对齐契约.md` 第 7 节（十条产品红线）。最常被问到的三条：学生和家长看不到任何等级；区域数据不排名、小样本不展示；AI 不下诊断，遇到危险表达立刻转人工。

需要知道的局限：视频和音频是占位，导出只有带水印的预览，小程序还没在真机上跑过。

### 3.2 我做 Web（教师端 / 管理端）

- 读：`docs/前后端对齐契约.md` 第 3、4、6、10 节。
- 启动：`npm run demo -- --no-miniapp`，或者只 `npm run dev:web`（不起后端也能跑，会用内置演示数据）。
- 页面在 `frontend/web/src/pages/`，菜单和谁能看到哪一页在 `src/layout/menus.tsx`。
- 请求只有一种写法：`useGet<T>(['key'], Routes.xxx, { params, query })` 读，`useAct(fn, ['要刷新的 key'], '成功提示')` 写。不要手写路径、请求头和目的码。
- 公共件在 `src/components/ui.tsx`（页头、面板、指标块、进度条、封面、图标、空状态、时间格式）。加新页面先看有没有现成的。
- 提示用 `toast.api.success(...)`（`src/api/toast.ts`），不要直接用 antd 的 `message`。

### 3.3 我做小程序（学生端 / 家长端）

- 读：`docs/前后端对齐契约.md` 第 6、7、10 节。**第 7 节的红线对学生端是硬约束。**
- 启动：`npm run dev:miniapp`，浏览器打开 <http://localhost:10086>。电脑上会自动收成手机宽度。
- 微信开发者工具：`cd frontend/miniapp && npm run dev:weapp`，导入 `frontend/miniapp` 目录（产物在 `dist/weapp`）。需要自己的 AppID，填在 `project.config.json`；真机调试时把 `TARO_APP_API_ORIGIN` 设成电脑的局域网地址。
- 三条容易踩的约定：行内样式的尺寸一律包 `px()`；颜色用 SCSS 变量不用 CSS 变量；改了 `contracts/` 要先 `npm run build:contracts`（小程序读的是构建产物）。
- 公共件在 `src/components/kit.tsx`，图标在 `icons.ts`。

### 3.4 我做后端

- 读：`docs/后端交接说明.md`，读完就可以独立开工。
- 终点：`npm run accept` 对着你的后端 68 项全部通过，并满足交接说明第 4 节（真实 PostgreSQL、行级安全、加密、审计）。
- 联调：你的后端起在 3000 端口后，`npm run demo -- --api` 或直接起前端，页面右下角显示“已连接后端”就是连上了。前端不用改代码。
- 只改 `backend/`。契约可以加接口和可选字段；改名、删字段、改含义先和前端商量。

### 3.5 我加内容、改文案（不需要懂前后端）

所有给学生、家长、老师看的内容都在 `contracts/src/mock/` 里，改完两端同时生效：

| 想改什么 | 改哪个文件 |
|---|---|
| 心理、学习、生涯、政策、文化、五育、榜样、家长课堂、教师微课的文章 | `content/` 下按频道分的文件 |
| 生涯卡（职业、行业、专业、过来人） | `content/careers.ts` |
| 活动、圈子和预置帖子、学习计划、专题、今日小行动、问卷、学生和家长的常见问题 | `library-student.ts` |
| 教师话术、提醒规则的说明、公告、教职人员的常见问题、助手的标准问答 | `library-staff.ts` |

一篇文章长这样（照着已有的抄一条改）：

```ts
item('psy17', 'psychology', 'article', '标题', '一句话简介', 4, '初中—高中', ['标签一', '标签二'], [
  '普通段落直接写。',
  '## 小标题',
  '- 要点',
  '> 划重点的一句话',
], ['文末记住的第一点', '第二点'])
```

规则：id 不能和已有的重复；每篇都要有来源、作者、授权（`item` 的默认值是平台自有内容，转载的要在最后一个参数里写明）；不用真实的人名、校名和个人经历；不出现“风险”“高危”和任何疾病名；政策和资助类内容写清出处，上线前由对口部门核对。

改完执行 `npm run check`，通过了再提交。封面图不用配，系统会按 id 自动生成。

### 3.6 我做测试、验收

- `npm run check` 是自动化的部分：四个类型检查 + 68 项接口验收。验收项的中文描述就是测试用例清单，在 `contracts/tools/accept.cjs` 里按十六组排列。
- `npm run check -- --build` 再加上 Web 和微信小程序的正式构建。
- 对着某一台机器上的后端验收：`node contracts/tools/accept.cjs http://那台机器:3000`。验收会写数据，要对着刚启动、只有种子数据的服务跑。
- 手工走查按角色来：登录页有九个教职身份，小程序有四个入口（老学生、老家长、新同学激活、新家长绑定）。每个角色能看到哪些页面见 `docs/前后端对齐契约.md` 第 6 节；跨端联动表列了“谁做了什么，谁那边会变”，逐行验证。
- Web 的“合规 → 权限矩阵”页面是从接口清单直接生成的，可以用来核对“这个角色到底能不能调这个接口”。
- 必查的红线：学生端和家长端的任何页面、任何接口响应里搜不到 `L1`/`L2`/`L3`、“风险”“高危”；区域看板里学生不足 10 人的学校不显示数值。

### 3.7 我整理软著或交付材料

- 功能清单：`docs/前后端对齐契约.md` 第 6 节的两张页面表就是按页面列的功能点，“用到的接口”一列可以直接对应到源码。
- 接口清单：`contracts/src/routes.ts`，或者 Web 里的“权限矩阵”页面（可以直接截图）。
- 截图：`npm run demo` 后按角色逐页截。学生端窗口宽度调到 390 左右。
- 源码行数、文件清单：`git ls-files` 列出全部入库文件；`npm run pack` 生成的 zip 就是一份不含依赖和构建产物的干净源码。
- 需求与架构原文在根目录的《云岭青心》产品说明.md 和《云岭青心》技术路径.md。

## 4. 一起协作的规矩

- 仓库：<https://github.com/Akakumo262/Yunlingqingxin>（私有，需要仓库所有者加为协作者）。拿不到仓库的成员用代码包，见第 5 节。
- 各改各的目录：前端改 `frontend/`，后端改 `backend/`，内容改 `contracts/src/mock/`。
- 改 `contracts/src/` 下的接口、类型、枚举：单独一个提交，说明以 `contracts:` 开头，并告诉其他人。新增接口、加可选字段可以直接做；改名、删字段、改含义要先商量。
- 提交之前 `npm run check` 全部通过。
- 不入库的东西：密钥和 `.env`、任何真实学生信息、演示用的视频素材（放 `demo-assets/`）。
- 对外文案里不出现“学习强国”。

## 5. 把代码发给拿不到仓库的人

```bash
npm run pack
```

在 `release/` 下生成一个 zip（约 1MB），内容和仓库里入库的文件完全一致：源码和文档，不含依赖、构建产物、密钥。对方解压后执行 `npm run setup`，再 `npm run demo` 即可。

## 6. 遇到问题

| 现象 | 原因和办法 |
|---|---|
| `npm run setup` 卡住或报网络错误 | `npm run setup -- --mirror` 直接用国内镜像 |
| 页面右下角显示“内置演示数据” | 3000 端口上没有后端。单端开发没问题；要看三端联动就用 `npm run demo` |
| 学生端做了操作，教师端没变化 | 两端没连同一个后端（同上）。或者教师端还没到自动刷新的时间，切一下页面 |
| 端口被占用 | 上一次的进程没停干净。关掉之前的命令行窗口；Windows 上可以在任务管理器里结束 node 进程 |
| 小程序报找不到 `@yunling/contracts` 里的某个导出 | 改了契约没构建：`npm run build:contracts` |
| 验收有几项失败，但没改过代码 | 多半是对着跑过一次验收的后端又跑了一次。`npm run check` 每次会起一个全新的，用它 |
| 刷新后回到登录页 | 有意为之：登录状态只放内存，不落本地存储 |
