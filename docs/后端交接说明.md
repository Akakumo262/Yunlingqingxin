# 云岭青心 · 后端交接说明

> 读者：负责后端的开发者（人或 AI）。读完这一份就可以独立开工，不需要再问任何人。
> 前端（Web 教师端/管理端 + 微信小程序学生端/家长端）已经全部做完，正跑在一个“模拟后端”上。
> 你的任务是把这个模拟后端换成真的。

## 0. 三句话说清任务

1. `contracts/` 里有 118 个接口的定义、类型和一份**可运行的参考实现**（`contracts/src/mock/`，纯内存）。接口分两批：第一批 59 个是安全底线与主流程，第二批 59 个是让平台日常用得起来的部分。
2. 你要在 `backend/` 里用真实的数据库和真实的安全机制实现同样的 118 个接口。
3. 根目录执行 `npm run accept`，对着你的后端 **68 项检查全部通过**，并满足第 4 节的工程要求，就算完成。

## 1. 你的权限：除了“必须”的，其余全部由你决定

这份文档里只有两类内容：

- **必须**：验收条件和产品红线。它们写得很具体，因为另一台电脑上的前端已经按它们写死了。
- **其余一切**：目录怎么拆、用什么库、表怎么设计、缓存和队列怎么用、测试怎么写、要不要加接口——**你是后端负责人，直接决定，不需要请示，也不需要在回复里征求同意**。

请按“资深工程师独立交付一个系统”的标准来做，而不是“小心翼翼补几个函数”。具体地：

- **做完整，不要留桩**。不要返回 501，不要留 `TODO: implement`，不要用“此处省略”“示例实现”收尾。118 个接口每一个都要有真实的数据读写。**把参考实现包一层直接当后端不算完成**：它是内存数据、没有租户隔离、没有加密，只是行为规格。
- **不要缩小范围**。如果觉得工作量大，就分阶段做完，而不是只做一部分然后列出“后续建议”。
- **不要因为缺少外部条件而停下**。没有微信 AppID、没有短信通道、没有大模型密钥、没有 Docker——都不是停工的理由，第 6 节给了每种情况的处理规则。
- **鼓励超出最低要求**。文档没提到但你认为一个认真的后端应该有的东西（限流、请求日志、健康检查细项、OpenAPI 文档、单元测试、种子脚本、Dockerfile……），直接加。
- **遇到文档没覆盖的取舍，自己选一个合理方案并在提交说明里写一句理由**，然后继续。
- 唯一需要停下来确认的情况：你认为必须**改名、删除或改变语义**某个已有接口字段（见第 5 节）。

## 2. 起步

```bash
npm install                 # 根目录。网络不稳可加 --registry=https://registry.npmmirror.com
npm run mock                # 启动模拟后端（3000 端口）——这就是“标准答案”
npm run accept              # 另开一个终端运行验收脚本，应看到 68 项全部通过
```

先把这三步跑通、看一遍输出，你就知道终点长什么样了。然后停掉模拟后端，启动你自己的后端在 3000 端口，再跑 `npm run accept`，从大量失败做到全部通过。

验收脚本每次都会写入数据，请对着**刚启动、只有种子数据**的服务运行。建议你提供一条命令一步完成“清库 → 迁移 → 导入种子 → 启动”，方便反复验收。

要看前端实际怎么调用你的接口：

```bash
npm run dev:web             # Web 端，http://localhost:5173，自动连 3000 端口的后端
cd frontend/miniapp && npm install && npm run dev:h5   # 小程序 H5 预览，http://localhost:10086，用手机尺寸看
```

## 4. 完成的定义

以下全部满足才算完成。

### 4.1 验收脚本

- `npm run accept` 对着你的后端 68 项全部通过。
- 不允许为了通过而修改 `accept.cjs` 里的断言。如果你确信某条断言本身有错，在提交说明里写清理由，并保持模拟后端仍能通过。
- 可以在后端自己的测试里加更多检查，越多越好。

### 4.2 数据与存储

- **必须用真实的 PostgreSQL**（14 及以上，推荐 16）。不接受 SQLite、内存 Map、JSON 文件作为最终实现——行级安全是本项目的硬要求，只有 PostgreSQL 能满足技术路径里的设计。
- 从空库执行迁移能一次成功；种子数据能重复导入而不报错。
- 种子数据里的 **id 必须保持原样**（例如学生 `s1`…`s36`、班级 `c1`、机构 `in1`、圈子 `cr1`…`cr8`、帖子 `p5`、量表 `ins1`…`ins8`、内容 `ct1`/`psy07`/`lrn12`、生涯卡 `cc1`/`cj01`、活动 `a01`…`a16`、计划 `pl1`、专题 `col1`、规则 `rr1`、推送 `pu1`）。前端和验收脚本会直接用这些 id。接口里的 id 一律是不透明字符串，内部用不用 uuid 由你决定。
- 演示账号必须齐全且可登录：`student01` `student02` `parent01` `parent02` `teacher01` `psy01` `leader01` `schooladmin01` `edu01` `cmt01` `inst01` `ops01` `audit01`。`student02`、`parent02` 初始为未激活。演示密码、学校码、短信验证码见 `data.ts` 顶部的常量。
- 种子里必须有一所学生数少于 10 人的学校，用来演示小样本抑制。

### 4.3 安全（这是本项目进政府采购的门槛，请认真做）

| 要求 | 说明 |
|---|---|
| 多租户隔离 | 所有业务表带租户标识，启用并强制行级安全（RLS）；应用用**非属主**账号连接；每个事务内设置租户上下文。写一个自动化测试证明：换一个租户上下文，查不到另一个租户的数据 |
| 权限分层 | 认证 → 角色 → 目的码 → 数据域（本班 / 本校 / 辖区 / 授权个案）→ 字段脱敏。前三层由路由表决定；后两层在业务代码里做，行为见参考实现 |
| 默认拒绝 | 没有声明权限的接口一律拒绝；列表查询必须带范围条件，禁止“查全表再过滤” |
| 敏感字段加密 | 打卡题记、谈话记录、干预记录、测评答案与分数、AI 对话、转介包，落库前加密（AES-256-GCM 即可），密钥来自环境变量，不入库不入仓。姓名、手机号加密存储并另存哈希用于查找 |
| 审计 | 所有写操作、敏感读取（见参考实现里的 `SENSITIVE_READS`）、被拒绝的访问都要留痕；追加式；哈希链用 SHA-256（`hash = SHA256(prev_hash + 规范化事件)`）；应用账号对审计表只有插入和查询权限。审计日志里不得出现业务明文 |
| 令牌 | 访问令牌 15 分钟。算法、刷新令牌轮换、撤销怎么做由你定，做得越完整越好 |
| 口令 | 用 Argon2id 或 bcrypt 存储，不存明文 |
| 错误输出 | 统一为 RFC 9457 的 problem+json，带 `code`；不泄露堆栈和 SQL |
| 输入 | 全部经 zod 校验；SQL 全部参数化 |

### 4.4 工程

- `backend/README.md` 写清：环境要求、一条命令启动、环境变量说明、如何跑验收、目录说明、你做的主要技术决策。
- TypeScript 严格模式下零报错；代码里没有残留的调试输出和被注释掉的大段代码。
- 提交历史按阶段分开，每个提交说明写清做了什么。

## 5. 契约可以怎么改

`contracts/` 是两台电脑共用的。规则很简单：

- **可以直接做**：新增接口；给响应加**可选**字段；给请求加**可选**参数；补充枚举值的中文标签；修正注释。改完同步更新参考实现 `mock/index.ts`，保证 `npm run mock` + `npm run accept` 仍然全绿，并在提交说明里列出改了什么。
- **需要先确认**：改名、删除字段、把可选改成必填、改变已有字段的含义或取值、改变状态码或错误码。这些会让另一台电脑上的前端坏掉。

## 6. 决策规则：缺东西的时候怎么办

| 缺什么 | 怎么做 |
|---|---|
| 没有 Docker | 本机安装 PostgreSQL，或用任何你能拿到的 PostgreSQL 实例。仓库里的 `docker-compose.yml` 只是方便，不是唯一途径 |
| 没有 Redis | 队列、限流、缓存先用进程内实现，接口抽象好，配了 `REDIS_URL` 就切到 Redis |
| 没有微信 AppID | `authWechatLogin` 做成适配器：配了 AppID/Secret 就调微信 `code2Session`；没配时走开发桩，规则与参考实现一致（code 以 `guardian` 开头是家长，以 `new` 开头是未激活新同学，其余是 `student01`） |
| 没有短信通道 | 通知做成通道适配器（站内、短信、电话、微信订阅消息）。没配置的通道写入通知记录表并打日志，状态如实记为已发送或失败。通知矩阵和超时升级的调度逻辑要真实实现（见 7.4） |
| 没有大模型密钥 | AI 做成提供方适配器：配了 `DEEPSEEK_API_KEY` 就走 DeepSeek（只允许国产模型，不接境外模型）；没配时用本地检索式回答，行为与参考实现一致。危机识别和输出后检**不能**依赖大模型是否可用 |
| 没有对象存储 | 视频、封面先存本地目录并通过带签名的短时效地址访问；接口抽象成对象存储适配器 |
| 文档互相矛盾 | `contracts/` 代码 ＞ 本文 ＞《技术路径》＞《产品说明》 |
| 文档没写 | 你来定。选更安全、对学生更友好的那个 |

## 7. 各模块必须做到什么

每个模块先列**必须**，再列**放手做**的方向。精确行为请对照参考实现里同名的处理函数。

### 7.1 身份与同意

必须：

- 演示登录、账号密码登录、微信登录三种入口都返回同样结构的令牌，带 `activated`。
- 学生激活：学校码 + 学籍号后四位，与名册匹配才激活；家长绑定：学校码 + 学籍号后四位 + 手机号 + 验证码，绑定后 `Me.children` 里出现孩子。
- 同意项按人保存，带版本号和时间；基础服务不可撤回（409）；撤回“成长问卷”后开始非娱乐测评返回 403 `CONSENT_REQUIRED`；撤回“成长圈”后圈子列表为空。
- 隐私仪表盘的访问记录来自真实的访问事件：教师每次查看学生卡片、测评报告、个案，学生那边就多一条“谁看了什么”。只写角色称呼，不写教师姓名和备注内容。

放手做：多设备管理、异常登录检测、教师端多因素认证、同意文本版本更新后的重新确认流程、14 岁以下学生的监护人同意前置。

### 7.2 学生日常

必须：

- 打卡带 `client_id` 时幂等；首页一次返回今天的打卡、近 7 天、小行动、推荐内容。
- **不计算也不返回连续打卡天数**。这是产品红线：不制造“断签”焦虑。
- 推荐内容只按学段、频道、兴趣标签来，不使用任何心理测评数据。
- 成长护照没有分数和排名，只有次数和证据。
- 家长摘要不含分数、逐题作答、逐日记录；孩子没开放“心情趋势”时，`week_text` 是通用文案；孩子有未关闭的紧急求助时出现 `crisis_notice`。

放手做：打卡触发的规则引擎做成可配置的（规则表 + 可解释的命中原因）；同一学生同类提示 7 天内不重复；微行动内容库；家长课程完成记录。

### 7.3 测评

必须：

- 三套自编问卷从种子导入（不要引入任何需要授权的量表原文）。
- 允许跳过任意题（答案为 null）；同一会话重复提交返回同一份报告。
- 报告只用“状态/建议”措辞，不出现疾病名、诊断、“高危”“高风险”。
- 结果偏低时生成一条 L1 提示，来源 `assessment_rule`，等待老师人工确认——**系统不直接给学生定级**。
- 原始分只给学生本人和心理教师；班主任、家长的任何接口都拿不到。
- 娱乐量表：不落库、不触发提示、教师的量表列表里看不到、提交后查报告返回 404。

放手做：计分规则配置化、复测提醒、量表版本管理、心理教师端的测评汇总。

### 7.4 求助、预警与观察

这是整个系统的安全底线，请做得最扎实。

必须：

- 学生一键求助 → 立即生成 L3 提示，确认时限 15 分钟；响应里只有“谁会在多久内联系你”，**没有任何等级字段和“风险”字样**。
- 通知矩阵：L1 通知班主任；L2 通知班主任 + 心理教师；L3 通知班主任 + 心理教师 + 校领导 + 家长。
- 超时自动升级：L3 提示 30 分钟未确认 → 通知校领导并标记升级；60 分钟 → 进入教体局督办列表。请用真实的定时调度实现，时限做成可配置（方便演示时调短）。
- 确认、升级、标记误报（必须写原因，422 否则）；误报不追责，不记入任何教师考核数据。
- 数据域：班主任只看到本班的提示和学生；心理教师、校领导看本校；教体局、审计员看不到任何个体提示（403）。
- 班主任看到的学生卡片里是心情**标签**趋势，不含学生写的题记原文。
- 班级看板：关注清单最多 5 人；心情分布只有人数，没有个人；没有任何排名。

放手做：通知的重试与死信、送达回执、备用通道切换；预警的 SLA 统计；强制报告（发现性侵、虐待等）的一键生成报告模板；督办工单的流转。

### 7.5 个案与转介

必须：

- 一案一码：案件号形如 `YL-2026-0001`，租户内唯一、递增。
- 状态机严格按 `CASE_TRANSITIONS`：非法迁移 409 `ILLEGAL_TRANSITION`；进入“跟进中”必须已有支持计划（422）；结案必须有结案摘要（422）；结案后不可再变更。
- 所有动作进时间线。班主任能看本班个案，但看不到心理教师写的面谈内容（`note` 不返回）。
- 更新个案要有并发保护（版本号或 ETag），防止两个人同时改互相覆盖。
- 转介生成“最小必要包”：案件号、脱敏后的学生信息、等级、已做过的支持的**标题**、转介原因，可选问卷摘要；**不含面谈内容**。有效期 7 天。
- 机构只能看到转给自己的转介，学生姓名脱敏（姓 + `*`）；机构确认接收、填写反馈后，反馈回到个案时间线。
- 学生、家长访问个案接口一律 403。

放手做：破窗访问（紧急情况下临时扩大权限，需理由、2 小时自动收回、事后复核、全量审计）；回访提醒（7 天 / 30 天）；转介 48 小时未确认的超时提醒；转介包的下载次数限制与撤回。

### 7.6 内容与生涯

必须：

- 内容必须有来源、作者、授权，缺一个都不能创建（422）。
- 审核状态机：创建 → AI 一审（至少做规则检查：缺授权、营销词、危机词）→ 团队二审 → 三审会签 → 发布。任何一步退回必须写原因。未发布的内容不出现在内容流里。
- 审核记录不可删除，每一步谁审的、什么时候、什么结论都要留下。
- 生涯卡每张都有来源和更新时间，支持按类型、地区筛选。

放手做：内容全文搜索（PostgreSQL 全文检索即可）；收藏、完成进度；版权到期自动下架；视频的签名播放地址；三审会签支持多方分别签（团委、教体局、心理机构）。

### 7.7 AI 成长助手

必须：

- 处理顺序：**输入护栏（危机识别、注入检测）→ 检索 → 生成 → 输出后检**。危机识别在最前面，命中后不调用模型，直接返回 `kind: 'crisis'`，回复里有 12355，并为老师生成一条 L3 提示（来源 `ai_guardrail`）。
- 回答必须带来源（内容或生涯卡的 id 和标题）。检索不到可靠资料时如实说不知道，不编。
- 输出后检：不得出现诊断结论、用药建议、“你有××症”。
- 每 5 轮返回 `remind_human: true`。
- AI 的工具/检索范围只有已发布的内容、生涯卡、政策资料。**不得查询任何个案、测评、打卡数据**。
- 对话加密保存，30 天后自动删除；不用于训练。发往模型的文本不带姓名、学号、手机号。
- 每条回答可追溯：用的模型、提示词版本、检索到的来源。

放手做：用 pgvector 做向量检索 + 重排；危机识别用“词表 + 模型”双检并建一个评测集（目标召回率 ≥95%）；每人每天的调用配额；模型超时降级到检索式回答；教师的备课助手用不同的提示词。

### 7.8 成长圈

必须：

- 学生在圈子里只有昵称和头像编号。帖子接口的响应里**不得出现**姓名、学校、班级、作者 id。
- **没有私信接口，也不要加**。
- 学生的前 3 条发言先审后发（`pending_review`）：作者自己能看到，其他人看不到。教师发言直接发布。
- 含手机号、微信/QQ、外链、拉群等内容直接拒绝（422）。
- 每条帖子可举报；举报进入审核队列；版主可通过、退回、删除。
- 发言里出现危机表达时，照常处理帖子，同时为老师生成一条 L3 提示。
- 班级圈只有本班成员能看和发。

放手做：发帖频率限制；违规分级处置（提醒 → 禁言 24 小时 → 禁言 7 天 → 封禁）与申诉；图片审核接口预留。

### 7.9 机构、组织、看板、审计

必须：

- 机构目录只返回已审核的机构，不暴露资质编号和联系人；入驻申请免登录提交；运营或团委审核。
- 区域看板全部是聚合数字。**任何统计口径的样本数小于 10 时，该值返回 null，学校行 `suppressed: true`**。不排名，按校名排序。响应里不得出现任何学生信息。
- 看板数字请从真实数据聚合（可以用物化视图或定时汇总表），不要写死。种子数据不够撑起好看的趋势图时，可以额外生成一批合成的历史汇总数据。
- 督办列表不含学生个体信息。
- 审计查询只对审计员开放；审计员访问任何业务接口都是 403。

放手做：名册的 Excel 批量导入（带逐行校验和错误行下载）；班级升级；区域报告一键导出 PDF（带水印）；数据导出的审批流；保留期限到期的自动删除任务。

### 7.10 第二批接口（`MoreRoutes`）

第二批的精确行为同样以 `mock/more.ts` 为准。下面只列容易做错、而前端已经按它写死的地方。

**通知是所有联动的落点。** 参考实现里每一处 `notify(...)` 都是一条必须产生的通知：给谁、标题、正文、`link.page`。前端按 `link.page` 跳转（Web 的映射在 `frontend/web/src/layout/menus.tsx` 的 `NOTICE_PATH`），所以 page 的取值不能改。通知按人隔离，未读数实时。

**成长护照的每一枚印记都有来源。** 小行动完成、活动反思、学习计划全部完成、学生自己记一件事，四种来源都调用同一个盖章动作（`source` 分别是 `action` / `activity` / `plan` / `self`）。同一天的小行动重复点、同一场活动重复写反思，不重复盖章。

必须：

- 搜索：一次返回内容、生涯卡、活动三类；`q` 为空只返回热门词；学生搜不到家长课堂和教师微课；未发布的内容搜不到。
- 收藏、看完、有没有用：按人保存；内容卡片上的 `favorited` / `completed` 是当前用户自己的。
- 学习计划：**不记“连续”，漏一天不清零**，任何一天都可以补；退出后已做的天数保留；全部做完盖一枚印记。
- 活动：名额满了不能报（409）；签到码不对 422；没签到不能写反思（409）；已签到不能取消报名（409）；`check_in_code` 只返回给这场活动的组织者；名单和见证只对组织者开放（403）；校外活动报名时通知家长。
- 求助进度：学生只看到三步（已通知老师 → 老师看到了 → 老师来找你聊）和一句状态，**响应里不出现任何等级**。
- 预约：时段被约走后不可再约（409）；取消后时段放回；心理教师看到学生姓名，学生自己的列表里没有 `student` 字段。
- 家校沟通单：一对一。班主任只看到自己发的；家长只看到发给自己的，打开列表即记为已读；另一位家长看不到（404）。
- 内容推送：学生首页的 `from_teacher` 来自本班的推送；`completed_count` 只返回给教师。
- 回访：三种来源（谈话时选了“过几天再聊”且之后没有新的谈话、跟进中的个案到了复盘日期、转介还没收到反馈）。
- 测评概览：人数不足 10 的问卷 `low_count` 返回 null。测评历史里没有娱乐问卷。
- 提醒规则：等级为 L3 的规则不能关闭（409）。
- 名册导入：先校验、不落库；错误逐行逐列指出，**不阻断整批**；提交时只导入通过校验的行。
- 公告：学生只看到发给所有人和学生的，家长同理；教职角色看到全部。
- 导出：申请 → 另一个人批准（自己批自己 403，已处理的再批 409）→ 带水印、24 小时有效、最多 3 次。
- 紧急访问：只对 L2、L3 的个案开放；理由不少于 20 字；最长 120 分钟自动收回；通知审计员和校领导；审计员事后复核。
- 区域报告文档：只有聚合数字，带导出人水印；小样本的学校写“样本不足”。

放手做：通知的多通道投递与送达回执；活动的候补名单；预约时段由心理教师自己排；名册的 Excel 文件上传与错误行下载；导出文件的真实生成（PDF/Excel 加水印）；系统状态接真实的探针；内容搜索用 PostgreSQL 全文检索或 pgvector。

## 9. 仓库里已有的后端代码
